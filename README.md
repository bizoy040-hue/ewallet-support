# E-Wallet Support v3: আপগ্রেড গাইড

Render Start Command অপরিবর্তিত: `gunicorn app:app` (পুরো অ্যাপ একটাই `app.py` ফাইলে)।

## নতুন কী আছে
- **রেফারেল:** প্রতি ইউজারের ইউনিক কোড ও লিংক (`/signup?ref=CODE`)। রেজিস্ট্রেশন সফল হলেই রেফারারের জন্য ৳৫০ **পেন্ডিং** রিকোয়েস্ট তৈরি হয় (ডিপোজিট লাগে না)। অ্যাডমিন প্যানেলে অনুমোদন/বাতিল করলে তবেই লেজারের মাধ্যমে টাকা যুক্ত হয়; রেফারার নোটিফিকেশন পান। স্ব-রেফারেল, একই ইউজারের দ্বিতীয় রেফারেল ও ডুপ্লিকেট পেমেন্ট ডাটাবেস স্তরেই আটকানো। একই আইপি থেকে সাইন আপ হলে অ্যাডমিন কার্ডে সতর্কতা দেখায়।
- **ম্যানুয়াল কমিশন:** স্বয়ংক্রিয় ডিপোজিট কমিশন নেই। Super Admin / Admin (পারমিশনসহ) / Finance মেম্বার আইডি, নাম বা ফোন দিয়ে ইউজার খুঁজে পরিমাণ ও বাধ্যতামূলক কারণসহ কমিশন দেন; লেজারে লেখা হয়, `commissions` টেবিলে (কে, কত, কেন, কখন) সংরক্ষিত হয় এবং ইউজার নোটিফিকেশন পান।
- **স্টাফ রোল (সার্ভারে বাধ্যতামূলক):**

| রোল | কী পারে |
|---|---|
| Super Admin | সব কিছু: স্টাফ ম্যানেজমেন্ট, সেটিংস, ব্যাকআপ, অডিট, ব্যালেন্স সমন্বয় |
| Admin | Super Admin-এর দেওয়া পারমিশন অনুযায়ী (ডিপোজিট, উইথড্র, ইউজার, রেফারেল, কমিশন, টিকিট, নোটিশ, অডিট, ব্যালেন্স সমন্বয়)। স্টাফ/সেটিংস/ব্যাকআপ নয়; Super Admin পরিবর্তন করতে পারে না |
| Finance | ডিপোজিট, উইথড্র, রেফারেল অনুমোদন, ম্যানুয়াল কমিশন, আর্থিক পরিসংখ্যান। স্টাফ/সেটিংস/ব্যালেন্স সমন্বয় নয় |
| Support | টিকিট ও উত্তর, ইউজারের মৌলিক তথ্য ও লেনদেন দেখা। পেমেন্ট অনুমোদন, কমিশন, ব্যালেন্স পরিবর্তন নয় |

  Super Admin স্টাফ তৈরি, এডিট, নিষ্ক্রিয়/সক্রিয়, রোল ও পারমিশন নির্ধারণ, অস্থায়ী পাসওয়ার্ড রিসেট এবং প্রত্যেকের অ্যাক্টিভিটি লগ দেখতে পারেন। নিষ্ক্রিয় বা রিসেট করা স্টাফের চলমান সেশন সঙ্গে সঙ্গে বাতিল হয়। Super Admin-এর পাসওয়ার্ড আগের মতোই `ADMIN_PASSWORD` এনভায়রনমেন্ট থেকে নিয়ন্ত্রিত।
- **ক্লায়েন্ট প্যানেল:** নিচের নেভিগেশন: হোম, হিস্ট্রি, রেফারেল, ইনসাইট, অ্যাকাউন্ট। রেফারেল পেজে কোড, লিংক, কপি/শেয়ার (WhatsApp সহ), পরিসংখ্যান ও ইতিহাস। সাপোর্ট হোম ও অ্যাকাউন্ট পেজ থেকে খোলে।
- **অ্যাডমিন পেজ:** ড্যাশবোর্ড, ডিপোজিট, উইথড্র, ইউজার, রেফারেল, কমিশন, স্টাফ, টিকিট, নোটিশ, সেটিংস, অডিট লগ, প্রোফাইল। প্রতিটি স্টাফ শুধু নিজের পারমিশনের ট্যাব দেখেন, আর সার্ভারও প্রতিটি রিকোয়েস্টে ডাটাবেস থেকে পারমিশন যাচাই করে।
- **VIP:** আপলোড করা কোডে VIP কোনো মেনু/পেজ/কোড ছিল না, তাই বাদ দেওয়ার মতো কিছু নেই। পুরনো ডাটাবেসে VIP-এর কোনো টেবিল/কলাম থাকলে সেগুলো মোছা হয় না (নিরাপত্তার জন্য), অ্যাপ সেগুলো ব্যবহার করে না।
- লগইন, সাইন আপ ও ড্যাশবোর্ড থেকে বারবার আসা পেমেন্ট-ডিসক্লেইমার সরানো হয়েছে (শুধু "শর্তাবলি" পেজে একবার আছে)। স্বাগত বার্তা অপরিবর্তিত।

## নিরাপদ ডিপ্লয় পরিকল্পনা (ধাপে ধাপে)
**১. আগে ব্যাকআপ (অত্যন্ত জরুরি)**
- পুরনো সাইটে অ্যাডমিন → সেটিংস → "ব্যাকআপ নামান" দিয়ে `.db` ফাইলটি ফোন/ড্রাইভে রাখুন। (Render ফ্রি প্ল্যানে ডিস্ক অস্থায়ী; Disk থাকলে `DATABASE_PATH=/var/data/ewallet.db` ও `UPLOAD_DIR=/var/data/uploads` দিন।)
- Render → Environment-এ আছে কিনা দেখুন: `SECRET_KEY`, `ADMIN_PHONE`, `ADMIN_PASSWORD` (শক্ত)।

**২. কপিতে পরীক্ষা (প্রোডাকশন ছোঁয়ার আগে)**
কম্পিউটারে ব্যাকআপের একটি **কপি** দিয়ে চালান:
```
pip install -r requirements.txt
cp ewallet-backup-XXXX.db test.db
DATABASE_PATH=test.db UPLOAD_DIR=./up ADMIN_PHONE=017XXXXXXXX ADMIN_PASSWORD='...' SECRET_KEY=test python app.py
```
অ্যাডমিন ড্যাশবোর্ডে "লেজার রিকনসিলিয়েশন" দেখুন এবং কিছু ইউজারের ব্যালেন্স আগের সাথে মেলান।

**৩. ডিপ্লয়**
GitHub-এ `app.py`, `requirements.txt`, `README.md` একই নামে রিপ্লেস করুন। Render নিজে ডিপ্লয় করবে।

**৪. ডিপ্লয়ের পর যাচাই**
- সুপার অ্যাডমিন দিয়ে লগইন, ড্যাশবোর্ডে "সব মিলেছে ✅" দেখুন।
- ইউজার/ব্যালেন্সের সংখ্যা ও কয়েকজনের ব্যালেন্স আগের ব্যাকআপের সাথে মেলান।
- সেটিংস থেকে নতুন ব্যাকআপ নামান।

**রোলব্যাক:** সমস্যা হলে পুরনো `app.py` ফিরিয়ে দিন এবং ব্যাকআপ `.db` রিস্টোর করুন (Render Shell/Disk-এ `DATABASE_PATH`-এর জায়গায় বসিয়ে সার্ভিস রিস্টার্ট)। নতুন কোড শুধু টেবিল/কলাম যোগ করে, তাই পুরনো কোডও নতুন ডাটাবেসে চলতে পারে। তবু ব্যাকআপ রাখুন।

## মাইগ্রেশন (স্বয়ংক্রিয়, কিছু মোছে না)
- প্রথম চালুর আগে ডাটাবেসের পাশে `ewallet.db.pre-v3-<সময়>.bak` নামে একটি কনসিস্টেন্ট কপি তৈরি হয় (একবারই, ওভাররাইট হয় না)। Render-এ এই ফাইলও অস্থায়ী ডিস্কে থাকে, তাই ধাপ ১-এর নিজের ব্যাকআপ বাদ দেবেন না।
- নতুন টেবিল: `referrals`, `commissions`। নতুন কলাম: `users.role/perms/referral_code/referred_by/signup_ip`, `audit.actor_id/ip`, `tickets.replied_by/replied_at`।
- পুরনো ইউজার, ব্যালেন্স, মেম্বার আইডি, পাসওয়ার্ড হ্যাশ, লেনদেন ও লেজার অপরিবর্তিত। প্রথম অ্যাডমিন Super Admin হয়; (থাকলে) অন্য পুরনো অ্যাডমিনরা "Admin" রোলে সব পারমিশনসহ থাকেন, দরকারে সংকুচিত করুন।
- প্রতিটি পুরনো ইউজার একটি রেফারেল কোড পায় (একবারই, পরে বদলায় না)। পুরনো কমিশন এন্ট্রি `commissions` টেবিলে কপি হয়।
- বারবার চালালেও ডুপ্লিকেট হয় না (idempotent)।
- **গুরুত্বপূর্ণ সংশোধন:** আগের সংস্করণের মাইগ্রেশন প্রতি রিস্টার্টে `opening_balance` এন্ট্রি নেই এমন সব ইউজারের জন্য তার বর্তমান ব্যালেন্সের সমান একটি এন্ট্রি যোগ করত। ফলে প্রথম স্টার্টের পরে সাইন আপ করা ও লেনদেন থাকা ইউজারের লেজার দ্বিগুণ হয়ে যাওয়ার ঝুঁকি ছিল। v3 শুধু লেজারে একেবারেই এন্ট্রি নেই এমন ইউজারের জন্য ওপেনিং এন্ট্রি দেয়। **আপনার প্রোডাকশনে আগে এমন হয়ে থাকলে** ড্যাশবোর্ডের রিকনসিলিয়েশনে অমিল দেখাবে; লেজার অপরিবর্তনীয় বলে এটি নিজে নিজে "ঠিক" করা হয় না, ব্যালেন্স না বদলে। ধাপ ২-এর কপি-পরীক্ষায় এটা আগেই দেখে নিন।

## এনভায়রনমেন্ট ভেরিয়েবল
| নাম | কাজ |
|---|---|
| SECRET_KEY | সেশন সিকিউরিটি (বাধ্যতামূলক) |
| ADMIN_PHONE / ADMIN_PASSWORD | Super Admin (এখান থেকেই নিয়ন্ত্রিত) |
| DATABASE_PATH | ডাটাবেস ফাইল (ডিফল্ট `ewallet.db`) |
| UPLOAD_DIR | স্ক্রিনশট ফোল্ডার |
| BASE_URL | (ঐচ্ছিক) রেফারেল লিংকের ডোমেইন, যেমন `https://yourapp.onrender.com` |

## সিকিউরিটি
CSRF টোকেন (সব POST), PBKDF2/scrypt পাসওয়ার্ড হ্যাশ, HttpOnly + SameSite + (Render-এ) Secure কুকি, সেশন ভার্সন (পাসওয়ার্ড বদল/নিষ্ক্রিয় করলে সব সেশন বাতিল), লগইনে ১৫ মিনিটে ৮ বার ভুলের পর লক, সাইন আপ রেট লিমিট, ইনপুট ভ্যালিডেশন, সার্ভার-সাইড রোল চেক, `X-Frame-Options`/CSP `frame-ancestors`, লগইনকৃত পেজে `no-store`। Render-এ প্রক্সির পেছনে প্রকৃত ক্লায়েন্ট আইপি ব্যবহার হয় (ProxyFix)।

## যা পরীক্ষা করা হয়েছে
পুরনো v2 কোডে তৈরি একটি ডাটাবেসের কপিতে (প্রোডাকশন নয়) ২১০টি স্বয়ংক্রিয় চেক পাস করেছে: মাইগ্রেশনে ব্যালেন্স/মেম্বার আইডি/লেনদেন অক্ষত ও idempotent; রেফারেল রেজিস্ট্রেশন ও ৳৫০ অনুমোদন/বাতিল; ডুপ্লিকেট ও স্ব-রেফারেল প্রতিরোধ; ডাবল-অ্যাপ্রুভ/ডাবল-সাবমিটে একবারই ক্রেডিট; ক্রেডিট ব্যর্থ হলে রোলব্যাক; ম্যানুয়াল কমিশন (সার্চ, বাধ্যতামূলক কারণ, রেকর্ড, নোটিফিকেশন); চার রোলের পূর্ণ অ্যাক্সেস ম্যাট্রিক্স; অনুমতিহীন ও অননুমোদিত অ্যাক্সেস; Super Admin অপরিবর্তনীয়তা; স্টাফ নিষ্ক্রিয়/পাসওয়ার্ড রিসেট; CSRF ও লগইন লক; শেষে প্রতিটি ইউজারের ব্যালেন্স = লেজারের যোগফল।

## যা নেই (ইচ্ছাকৃত)
VIP, ডিপোজিটের শতকরা স্বয়ংক্রিয় কমিশন, PostgreSQL (এখনো SQLite)।
